==================================================================
RESUMO DA VIEW: PRODUTOS DO CLIENTE
==================================================================
Ficheiro: paw_market/views/cliente/products.ejs

Esta página permite ao cliente visualizar a lista de produtos disponíveis para compra, pesquisar, filtrar, adicionar ao carrinho e iniciar a comparação de produtos.


--------------------------------------------------
1. ESTRUTURA GERAL
--------------------------------------------------
A página está dividida em duas partes principais:
- Barra lateral (sidebar): Menu de navegação à esquerda, comum a todas as páginas do cliente.
- Conteúdo principal (page-wrapper): Onde aparece a barra de pesquisa/filtros e a lista (grelha) de produtos.


--------------------------------------------------
2. BARRA DE PESQUISA E FILTROS (<form method="GET" action="/cliente/products">)
--------------------------------------------------
No topo da página, existe um formulário para ajudar o cliente a encontrar o que procura. Este formulário usa o método GET, o que significa que os critérios de pesquisa ficam visíveis no endereço da página (ex: /cliente/products?search=maca&category=123).

Tem 3 opções:
A) Pesquisar por nome do produto (input de texto)

1. O Formulário Base
.<form method="GET" action="/cliente/products" style="...">
-<form>: É o agrupador. Diz ao browser que tudo aqui dentro faz parte de um conjunto de dados a enviar.
-method="GET": É a forma como envia os dados. Ao usar o GET, as palavras que pesquisares vão ficar visíveis no endereço (URL) do browser (ex: /cliente/products?search=leite). É ideal para pesquisas porque permite ao cliente copiar o link e partilhar a página com a pesquisa já feita.
-action="/cliente/products": É o destino. Diz para que página (ou Rota no backend) esta informação de pesquisa vai ser enviada.
-style="...": É a formatação visual. Usa display: flex; gap: 12px para colocar a caixa de pesquisa lado a lado com os outros filtros, mantendo um espaço entre eles de 12 píxeis. O flex-wrap: wrap garante que se a janela do browser for encolhida (ex: telemóvel), os campos passam para a linha de baixo para não ficarem esmagados.

2. A Caixa (Div) do Campo de Pesquisa
-<div style="flex: 2; min-width: 200px;">
-É um contentor (wrapper) que agrupa o título (label) e a caixa onde escreves (input).
-flex: 2: Isto significa que esta área de pesquisa vai ser duas vezes mais larga que os dropdowns de categoria ou ordenação (que têm flex: 1). Faz sentido a área de texto ser maior para o cliente conseguir ver o nome completo que está a escrever.
-min-width: 200px: É a proteção. Impede que a caixa de pesquisa encolha demais em ecrãs mais pequenos, garantindo pelo menos 200 píxeis de largura.

3. A Etiqueta (Label)
-<label style="...">Pesquisar</label>
-É simplesmente o textozinho que aparece logo acima da caixa a dizer ao cliente o que fazer (aqui, a dizer "Pesquisar").
-O estilo usado mete-o cinzento (color: #666) e ajusta a proximidade à caixa abaixo.

4. A Caixa de Texto Própriamente Dita (Input)
-<input type="text" name="search" value="<%= search %>" placeholder="Nome do produto..." style="...">
-type="text": Indica que é um campo aberto para o cliente digitar letras e números livremente.
-name="search": Esta é a parte mais importante para o código. É como o backend reconhece a informação. Quando envias a pesquisa, o servidor recebe os dados dizendo procurar por search.
-value="<%= search %>": Isto é código dinâmico (EJS). Funciona assim: se o cliente escrever "Maçã" e pesquisar, a página recarrega para lhe mostrar as maçãs, mas a palavra "Maçã" desapareceria da caixa. Este bocado de código vai buscar a variável search ao backend e volta a preencher a caixa sozinha com aquilo que o utilizador já lá tinha escrito antes.
-placeholder="Nome do produto...": É a dica visual. Aquele texto cinzento claro que fica dentro da caixa vazia e desaparece logo que começas a escrever.
-style="...": Apenas a estética. Garante que ela ocupa 100% da largura da sua div, dá espaço interior (padding) para o texto não colar às bordas, coloca uma borda cinzenta fina (border: 1px solid #ddd;) e arredonda bastante as pontas (border-radius: 8px).

B) Filtro por categoria (dropdown/select com as categorias disponíveis)

1. A Caixa do Filtro
-<div style="flex: 1; min-width: 160px;">
-Agrupa o título e o menu das categorias.
-flex: 1: Ao contrário da barra de pesquisa que tinha flex: 2, aqui usamos flex: 1 para que estecupe apenas 1 parte do espaço (ou seja, tem metade da largura da caixa de pesquisa de texto baseada no ecrã livre).
-min-width: 160px: Impede que a caixa fique totalmente esmagada em ecrãs pequenos. Garante no mínimo 160 píxeis para que as palavras consigam ser lidas sem estarem cortadas.

2. A Etiqueta (Label)
<label style="...">Categoria</label>
- O textozinho por cima do filtro que indica ao cliente do que trata.
- display: block: Força esta palavra a ocupar uma linha só para ela, atirando a caixa da categoria automaticamente para baixo.
- margin-bottom: 4px: Dá um pequeno espaço para a palavra não ficar "colada" à caixa.

3. O Caixote do Dropdown Principal (Select)
<select name="category" style="...">
- <select>: É uma das tags mais comuns na web. Cria uma caixa clicável que abre aquela lista pendente (dropdown menu) para escolheres uma opção.
- name="category": Isto é o que importa! Quando o cliente escolher algo e pesquisar, o valor escolhido é enviado para o URL/backend focado nesta etiqueta category. (Ex: ficará ?category=id555...).
- style="...": Estética pura para se aproximar à barra de pesquisa. Dá preenchimento agradável (padding), largura de 100% da div onde está, uma linhazinha cinzenta macia e bordas curvas. O fundo branco garante que não herda o cinzento possível de outros cantos.

4. A Opção Predefinida
-<option value="">Todas</option>
- É uma escolha fixa. É a escolha em que o site inicia e indica que o cliente quer ver todas as categorias.
- O value="" fica vazio de propósito, porque não queremos mandar nenhum ID específico para o backend se não houver um filtro de categoria selecionado ativamente.

5. O Ciclo EJS que Preenche o Resto das Opções (As Dinâmicas)
-<% categories.forEach(function(cat) { %>...<% }) %>
- Este código (do EJS) não é visto pelo utilizador. Ele espeta um ciclo (um "loop") que percorre a lista de Categorias vindas da base de dados (MongoDB), e repete a construção dos dados que estiverem pelo "meio". Para cada categoria que exite, vai "cuspir" os dados ali pelo meio:

6. A Opção para cada Categoria
---<option value="<%= cat._id %>" <%= selectedCategory===cat._id.toString() ? 'selected' : '' %> > <%= cat.name %> </option>---
-value="<%= cat._id %>": O que é enviado ao backend, enviamos o ID do banco de dados . Para o código o ID é muito mais fácil e 100% fiável para identificar a pasta certa.
-O "Truque" do Selected (<%= selectedCategory === cat._id.toString() ? 'selected' : '' %>): Isto serve para que o sistema se "lembre" da categoria escolhida quando a página dá refresh. Quando clicas para pesquisar algo, a página recarrega. Este bocadinho de código analisa assim: "Espera aí! A categoria que eu tou a desenhar agora no ecrã era a que o utilizador escolheu antes do site recarregar?". Caso seja a mesma, envia a palavra selected para lá. O browser quando lê este "selected" bloqueia o <select> na frente do cliente para ele focar-se exatamente na opção certa onde clicou (para o ecrã não resetar sempre na palavra "Todas").
-<%= cat.name %>: O que o cliente consegue ver à vista desarmada na lista do site (Ex: "Higiene", "Carne") e não os esquisitos IDs que usamos pelo meio no value.

C) Ordenar (dropdown para ordenar o preço do Menor->Maior ou Maior->Menor)

1. A Div e a Etiqueta (Label)
<div style="flex: 1; min-width: 160px;">: Tem exatamente a mesma configuração que o filtro de categorias. Vai ocupar a mesma largura (1 parte do espaço da grelha de pesquisa) e protege contra o esmagamento com o limite de 160 píxeis.
<label ...>Ordenar por</label>: Apenas o título a flutuar por cima da caixa para organizar visualmente.
2. O Dropdown de Ordenação
<select name="sort" style="...">

name="sort": A palavra mágica para o servidor entender do que se trata isto. Quando o cliente escolhe algo, será enviado como parâmetro de sort (ordenação). No URL ficará algo como ?sort=preco_asc.
A estilização (o <style...>) é um puro "copiar/colar" da caixa da categoria para manter o design igual e agradável à vista.

3. As 3 Opções Disponíveis ()
Opção 1: <option value="">Mais recentes</option>
É a predefinida. Tem value="" vazio porque não é preciso avisar o servidor para ordenar por preço. O comportamento normal é a base de dados já cuspir naturalmente os produtos pela data em que os supermercados os inseriram lá.

Opção 2: <option value="preco_asc" <%= ... ? 'selected' : '' %>>Preço: Menor → Maior</option>
value="preco_asc": É a "chave-código" que segue para o servidor (asc = ascendente). Avisa o backend para puxar a lista organizando do mais barato até ao mais caro.
O código de EJS: Verifica internamente "A variável chamada selectedSort tem guardada a palavra 'preco_asc' desta pesquisa?". Se for verdade, joga para lá um selected para que quando a página voltar a desenhar-se a listar produtos, a barra não faça reset para os "Mais recentes" aos olhos do cliente.

Opção 3: <option value="preco_desc" <%= ... ? 'selected' : '' %>>Preço: Maior → Menor</option>
É a lógica espelho à de cima, mas manda a chave preco_desc (desc = descendente) para organizar os artigos na grelha dos mais caros até chegar aos mais baratos. Funciona da mesma forma para fixar a seleção com o selectedSort.



--------------------------------------------------
3. MENSAGENS DE ERRO
--------------------------------------------------
A página tem uma secção preparada para mostrar erros. Avalia a variável "erro" vinda do servidor:
- erro === 'sem_stock': Mostra "Produto sem stock disponível."
- erro === 'supermercado_diferente': Avisa o utilizador que não pode adicionar produtos de supermercados diferentes ao mesmo tempo. Tem de finalizar a encomenda primeiro ou limpar o carrinho atual.


--------------------------------------------------
4. LISTA DE PRODUTOS
--------------------------------------------------
Os produtos aparecem organizados numa grelha (grid).
Se não houver produtos na pesquisa, mostra a mensagem "Nenhum produto encontrado".

Para cada produto na grelha, o sistema mostra:
- Imagem: Se o produto tiver uma imagem associada mostra a imagem, senão mostra um ícone padrão (🛒).
- Categoria.
- Nome do produto.
- Nome do supermercado.
- Preço e Quantidade de Stock: Se o stock for maior que zero mostra "X em stock" a verde. Se for zero mostra "Sem stock" a vermelho.


--------------------------------------------------
5. BOTÕES DO PRODUTO (ADICIONAR E COMPARAR)
--------------------------------------------------
Cada produto tem dois botões de ação:

A) Adicionar ao Carrinho (<form method="POST" action="/cliente/cart/add">)
   - Contém o ID do produto e a quantidade definida para "1" (escondidos / hidden).
   - Ao clicar, o formulário envia um pedido POST para inserir este produto no carrinho.
   - Se o stock do produto for zero ou menor, este botão fica bloqueado (disabled) e muda de cor para cinzento para indicar que não pode ser clicado.

B) Comparar (Link)
   - É um link (<a href="...">) que leva o utilizador para a página de comparação.
   - Usa o nome do produto no endereço (/cliente/compare?productName=NomeDoProduto), o que permite à página seguinte (compare.ejs) saber que produto o cliente quer procurar noutros supermercados.


--------------------------------------------------
6. EXEMPLO PRÁTICO
--------------------------------------------------
1. O cliente procura por "Leite" e clica em Pesquisar.
2. A página recarrega mostrando os pacotes de leite de vários supermercados.
3. O cliente vê um leite do supermercado A que tem stock, e num botão "Adicionar".
4. Ao clicar no botão, o ID do produto é enviado (POST) para o controlador do carrinho.
5. O controlador do carrinho adiciona o produto e volta a carregar a página de produtos, garantindo que o número no carrinho ou o estado atualizado aparecem.
6. Se o cliente clicar no botão "Comparar", ele é enviado para a página de comparação com a referência do "Leite", vendo imediatamente que existem opções mais baratas noutros supermercados.
